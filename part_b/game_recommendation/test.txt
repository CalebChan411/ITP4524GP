GameLens - Terminal Test Guide
=============================
Windows, macOS and Linux. Requires Python 3.12 and the complete project files.
Manual commands for the four models and two evaluation scenarios.
Copy command lines only, one section at a time.

1. Open the project
-------------------
Extract the complete project ZIP before running any commands.
Open the game_recommendation folder containing this test.txt in your terminal.
VS Code: File > Open Folder > select game_recommendation > Terminal > New Terminal.
The current folder must contain game_recommendation.py and requirements.txt.
The commands below work regardless of your username or download location.

2. Set up your own environment
------------------------------
Choose ONE option matching your operating system and terminal.
Each person creates their own environment; exclude .venv* folders when sharing.

Windows - PowerShell:
py -3.12 -m venv .venv312
.\.venv312\Scripts\Activate.ps1

Windows - Command Prompt (CMD):
py -3.12 -m venv .venv312
.venv312\Scripts\activate.bat

macOS / Linux - bash or zsh:
python3.12 -m venv .venv312
source .venv312/bin/activate

If PowerShell blocks activation, use the CMD option in the same project folder.
If py or python3.12 is not found, install Python 3.12 and reopen your terminal.
Python 3.12 installers: https://www.python.org/downloads/release/python-31210/
On Linux, your distribution may also require its Python 3.12 venv package.

Confirm Python 3.12.x, then install dependencies (all operating systems):
python --version
python install_requirements.py

Success: "Installation complete. Run game_recommendation.py next."
For later sessions, reopen this folder and run your activation command above.
The remaining commands are the same on Windows, macOS and Linux.
VS Code Run button: use Python: Select Interpreter and choose the project's
.venv312 interpreter. Terminal activation alone may not change that selection.

3. Optional rebuild and evaluation
----------------------------------
The reference models and results are included. For a demonstration, go to section 4.
Use the following command to rebuild datasets, models, metrics and plots.
It replaces the generated files; use a separate project copy to retain originals.
This uses the supplied data snapshot without fetching Steam data.

python game_recommendation.py

Success: a held-out results table and saved model/results paths appear.
Word reports, slides and the presentation script are not updated by this command.
Reruns regenerate local measurements/plots and retain the reporting reference.

4. View user history and recommendations
----------------------------------------
Each command prints the user ID, known games with play hours, and the top five
recommendations from each model. These commands load the saved models.
User IDs represent anonymised historical players, not website login accounts.
Interest is inferred from play time >= 1 hour; it is not an explicit favourite.

Default example user:
python game_recommendation.py --recommend

User 00919b5131b1b3a8 - history includes Dota 2 and XCOM: Enemy Unknown:
python game_recommendation.py --recommend 00919b5131b1b3a8

User 0004cb703639fc12 - history includes Team Fortress 2 and Garry's Mod:
python game_recommendation.py --recommend 0004cb703639fc12

User 00084358a8270e14 - history includes Left 4 Dead 2 and Terraria:
python game_recommendation.py --recommend 00084358a8270e14

User 00560a5025e790d4 - history includes Orcs Must Die! 2 and Torchlight II:
python game_recommendation.py --recommend 00560a5025e790d4

To try others, copy a complete user_id from data/splits/training.csv and replace
the ID after --recommend. The current program uses existing histories;
manually choosing favourite games is not an implemented command.

Recommendation columns:
model_name = method; rank = recommendation order; title = game; score = ranking score.
Rank 1 comes first. Scores differ by model and are not probabilities.

5. View test results in Terminal
--------------------------------
Test 01: use each user's full final-training history as the query.
Test 02: use only their most-played known game as the query.
Both use the same hidden test games and exclude all known training games.
Test 02 checks reduced input for existing users, not genuinely new users.

Approved Windows reference (full-precision CSVs, shown to four decimals):
python -c "import json,pandas as pd; r=json.load(open('results/experiment_summary.json',encoding='utf-8'))['reporting_reference']; print(r['source']); print(pd.DataFrame(r['metrics'])[['model','history','k','precision','recall','hit_rate','coverage']].round(4).to_string(index=False))"

The supplied CSVs, models, report, slides and figures use this Windows reference.
Its archive metadata records Python 3.14.2; the supplied Python 3.12.10 console
matches the Top-5 values to four decimals. Python 3.12 remains recommended locally.

6. Read the results
-------------------
Model keys: popularity = Model 01; content_tags = Model 02;
content_full = Model 03; user_cf = Model 04.
k: 5 = top five recommendations; 10 = top ten recommendations.
Precision: fraction of recommendations that match hidden test games.
Recall: fraction of hidden test games recovered by the recommendations.
Hit rate: fraction of users with at least one matching recommendation.
Coverage: fraction of catalogue games recommended across all users.
Precision and Recall are averaged per user. Values are fractions: 0.30 = 30%.
Compare models at the same test and k. Higher coverage alone does not mean better
matching. Unobserved games are not confirmed dislikes.

Metric illustration (PPT slide 13): hidden games I/J; recommended I/K/L/M/N.
One hit gives Precision@5 = 1/5 = 20% and Recall@5 = 1/2 = 50%.
Model 04's cosine/weighted-support illustration is on slide 10.
These are teaching examples, separate from the measured CSV results.
The 20-slide presentation and script assign five slides to each speaker.

validation_results.csv: candidate settings and validation metrics.
experiment_summary.json: local-run settings plus the approved reporting_reference.
Selection uses validation Recall@5, then Precision@5; tests assess that selection.
results/plots/: three data-analysis plots and two test-comparison plots.

Keep reference-run files together. Local reruns can differ, especially for user
CF neighbours with equal similarity; do not mix their metrics with the reference.
